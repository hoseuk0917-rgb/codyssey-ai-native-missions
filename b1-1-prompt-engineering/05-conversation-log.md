# 05. 10턴 이상 실행 로그

## 1. 시나리오

사용자가 B1-1 과제 제출을 위해 **“AI 프로젝트 요구사항 정리·검증·제출문서 초안 작성 봇(CheckBot)”**을 설계한다.
대화 중간에 요청 목적을 다시 설명하고, 보너스 과제 정보를 뒤늦게 제공하고, 쉬운 버전·페르소나·Few-shot·환각 검증·README·멀티모달 다이어그램·최종 체크리스트까지 단계적으로 확장한다.

## 2. 문맥 유지 검증 기준

- 이전에 확정한 요구사항을 유지한다.
- 조건 변경이 들어오면 변경된 부분만 반영한다.
- 개인정보, 계정정보, API Key, 토큰을 노출하지 않는다.
- 문서에 없는 사실은 “확인 필요”로 표시한다.
- 사용자 의도를 잘못 해석한 경우, 다음 턴에서 수정 지시를 통해 결과를 개선한다.
- 추가 정보가 뒤늦게 제공되면 기존 답변을 그 정보 기준으로 보정한다.

```text
먼저 이 봇의 과업 정의, 대상 사용자, 입력 데이터, 출력 결과를 제출문서용으로 정리해줘.
단, 문서에 없는 내용은 확인 필요로 표시하고, 개인정보나 API Key는 포함하지 않는 방향으로 설계해줘.
```

**문제 지점**

AI가 사용자의 요청을 “실행 로그 수집을 위한 새 대화”로 이해하지 못하고, 기존 문서 반복 여부를 확인했다.

```markdown
## 필수 요구사항
- LLM 3종 이상 비교
- Few-shot 예시 3개
- 환각 검증 질문 5개 이상
- 대화 로그 10턴 이상
- 프롬프트 v1→v2 개선 이력
- 개인정보/API Key 미포함
```

### Turn 10 — 멀티모달 워크플로우 다이어그램 설명 추가

**User**

```text
보너스 멀티모달 확장을 위해 시각 자료로 만들 워크플로우 다이어그램 설명을 추가해줘.
```

**AI**

```markdown
### Bonus 2 — 멀티모달 확장: CheckBot 워크플로우 다이어그램

[시작]
  ↓
[입력 단계] 사용자가 미션 설명서 텍스트를 붙여넣기
  ↓
[보안 검사] 개인정보 / API Key / 토큰 포함 여부 확인
  ├─ 감지됨 → [경고 출력] 제거 후 재입력 요청 → 입력 단계로 복귀
  └─ 이상 없음 → 요구사항 분석
  ↓
[요구사항 분석] 필수 / 선택 / 제약 / 보안 항목 분류
  ↓
[누락 위험 항목 검사]
  ↓
[확인 필요 항목 추출]
  ↓
[체크리스트 완료 여부 판단]
  ├─ 미완료 → 보완 요청
  └─ 완료 → 제출문서 초안 생성
  ↓
[최종 출력] 체크리스트 + 초안 3종 + 확인 필요 목록
```

## 4. 문제 지점과 개선 요약

| 지점 | 문제 | 수정 방식 | 개선 결과 |
|---|---|---|---|
| Turn 1 | AI가 실행 로그 수집 목적을 이해하지 못함 | Turn 2에서 실행 로그 수집 목적과 새로 작성 조건을 명시 | 과업 정의·입력·출력 구조를 재작성함 |
| Turn 3 | 초급자용 표현 필요 | 쉬운 설명 요청, 기존 목적과 보안 조건 유지 지시 | 개발 경험이 부족한 학습자용 설명으로 변환됨 |
| Turn 4 | 보너스 정보가 현재 대화에 없음 | AI가 임의 생성하지 않고 확인 질문 | 환각 방지 원칙을 지킴 |

| Turn 6 | 페르소나가 더 실무적이어야 함 | 실무형 검토 코치로 강화 요청 | 이름/역할/전문 분야/말투/금지 사항/우선순위 정리 |
| Turn 7 | Few-shot 필요 | 좋은 입력 2개 + 모호한 입력 1개 요청 | Few-shot 요건 충족 |
| Turn 8 | 환각 검증 필요 | 기대 정답/판정 기준/참고 근거 포함 요청 | 환각 검증 질문 5개 구성 |

| Turn 11 | 최종 제출 전 누락 점검 필요 | 최종 체크리스트 요청 | 제출 전 점검표 생성 |

## 5. 최종 판정

| 항목 | 판정 | 근거 |
|---|---|---|
| 10턴 이상 대화 | Pass | Turn 1~11, 총 11턴 수행 |
| 조건 변경 포함 | Pass | Turn 3에서 초급자용 변경, Turn 5에서 보너스 추가 정보 제공 |
| 추가 정보 반영 | Pass | Turn 5에서 보너스 과제 2개 반영 |
| 문제 발생 지점 기록 | Pass | Turn 1 의도 오해, Turn 4 보너스 정보 부족 상황 기록 |
| 수정 결과 요약 | Pass | 각 문제 지점별 개선 결과 기록 |
| 문맥 유지 | Pass | 개인정보/API Key 금지, 확인 필요 표시, 쉬운 설명 조건 유지 |
| 환각 억제 | Pass | 문서에 없는 보너스 정보를 임의 생성하지 않고 확인 질문 수행 |
| 제출 가능성 | Pass | 섹션/번호/표/요약 구조로 정리 완료 |

## 6. 제출 시 주의사항

- 실제 제출 전 계정명, 이메일, API Key, 토큰이 보이는 캡처는 마스킹한다.
- 제출 기한, 제출 형식, 배점 기준은 미션 설명서에 명시되지 않았으므로 운영자 또는 제출 플랫폼에서 확인한다.
- GitHub 링크 제출 가능 여부도 별도 확인한다.
