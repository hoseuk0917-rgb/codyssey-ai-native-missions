# 05. 10턴 이상 실행 로그

## 시나리오

사용자가 B1-1 과제 제출을 위해 “AI 프로젝트 요구사항 정리·검증·제출문서 초안 작성 봇”을 설계한다. 대화 중간에 요청 목적을 명확히 하거나 조건을 변경하고, AI가 기존 조건을 유지하면서 변경된 부분만 반영하는지 확인한다.

## 문맥 유지 검증 기준

- 이전에 확정한 요구사항을 유지한다.
- 조건 변경이 들어오면 변경된 부분만 반영한다.
- 개인정보와 민감정보를 노출하지 않는다.
- 문서에 없는 사실은 확인 필요로 표시한다.
- 사용자 의도를 잘못 해석한 경우, 다음 턴에서 수정 지시를 통해 결과를 개선한다.

```text
먼저 이 봇의 과업 정의, 대상 사용자, 입력 데이터, 출력 결과를 제출문서용으로 정리해줘.
단, 문서에 없는 내용은 확인 필요로 표시하고, 개인정보나 API Key는 포함하지 않는 방향으로 설계해줘.
```

```text
위에서 이미 작성한 설계 문서(섹션 1~4)와 동일한 내용입니다.

- 형식 변환(Word/PDF 등)이 필요하시면 말씀해 주세요.
```

```markdown
# "AI 프로젝트 요구사항 정리·검증·제출문서 초안 작성 봇" 설계 개요

---

## 1. 과업 정의

AI 교육 과정 수강생이 미션 설명서를 입력하면, 요구사항을 필수·선택·제약·보안으로 분류하고 누락 위험 항목을 강조한 뒤 제출문서 초안을 생성하는 업무 자동화 과업이다.

**해결하려는 문제:**
- 미션 설명서의 세부 조건을 오독하거나 누락하여 제출물이 기준 미달이 되는 반복 문제
- 필수/선택 구분, 보안 제약, 검증 항목 등을 별도로 정리하는 데 드는 시간 낭비

---

## 2. 대상 사용자

| 항목 | 내용 |
|------|------|
| 주 사용자 | AI 교육 과정 수강생 |
| 기술 수준 | 프롬프트 엔지니어링 학습 중 (입문~중급) |
| 사용 시점 | 미션 설명서 수령 직후 / 제출 전 최종 점검 시 |
| 사용 목적 | 요구사항 누락 방지 및 제출문서 초안 신속 확보 |

---

## 3. 입력 데이터

| 구분 | 내용 | 비고 |
|------|------|------|
| 필수 | 미션 설명서 원문 텍스트 | 복사·붙여넣기 또는 파일 |
| 선택 | 업무 과업 시나리오 | 없으면 봇이 확인 요청 |
| 선택 | 비교할 LLM 모델명 목록 | 없으면 봇이 확인 요청 |
| 선택 | 기존 작성 초안 | 있을 경우 검토 모드로 전환 |

**입력 제약:**
- 개인정보(이름·전화번호·주소), 계정정보, API Key, 토큰은 입력에 포함하지 않는다.
- 위 정보가 감지되면 처리를 중단하고 제거 후 재입력을 안내한다.

---

## 4. 출력 결과

**출력 1 — 요구사항 분석표**

- 필수 항목 체크리스트 (항목명 / 충족 여부 / 비고)
- 선택·보너스 항목 (문서에 없으면 "확인 필요" 표시)
- 누락 시 위험도 높은 항목 ⚠️ 강조

**출력 2 — 제출문서 초안**
- 문서 1: LLM 비교 보고서 템플릿
- 문서 2: 시스템 설계 문서 템플릿
- 문서 3: 실행 로그 템플릿
- 각 섹션에 작성 가이드 주석 포함

**출력 3 — 확인 필요 항목 목록**
- 미션 설명서에 명시되지 않아 추측 불가한 항목만 별도 정리

**형식 규칙:**
- Markdown 구조, 섹션별 번호 부여
- 표·체크리스트 혼용
- 제출문서 초안은 요구사항 분석 완료 후에만 생성
```

```markdown
# "AI 프로젝트 요구사항 정리·검증·제출문서 초안 작성 봇" 설계 개요 (쉬운 버전)

---

## 1. 이 봇은 무슨 일을 하나요?

미션 설명서를 붙여넣으면, 봇이 대신 읽고 이렇게 도와줍니다.

- **"뭘 제출해야 하지?"** → 필수 제출물 목록을 정리해 줍니다.
- **"뭘 빠뜨렸지?"** → 놓치면 안 되는 항목을 경고로 알려줍니다.
- **"어떻게 써야 하지?"** → 제출문서 초안 틀을 잡아줍니다.

> 문서에 나와 있지 않은 내용(제출 기한, 배점 등)은 절대 추측하지 않고 **"확인 필요"** 로 표시합니다.

---

## 2. 누가 쓰나요?

| 항목 | 내용 |
|------|------|
| 주 사용자 | AI 교육 과정을 듣는 수강생 |
| 기술 수준 | 코딩·개발 경험이 없어도 됩니다 |
| 언제 쓰나요 | 미션을 받았을 때 / 제출 전 마지막으로 확인할 때 |
| 왜 쓰나요 | 요구사항을 빠뜨리지 않고, 문서 초안을 빨리 만들기 위해 |

---

## 3. 무엇을 입력하나요?

**반드시 넣어야 하는 것**
- 미션 설명서 전체 텍스트 (복사해서 붙여넣기)

**있으면 같이 넣어도 되는 것**
- 내가 생각한 업무 시나리오
- 비교하려는 AI 모델 이름
- 이미 쓴 초안 (검토해 달라고 할 때)

**⚠️ 절대 넣으면 안 되는 것**
- 이름, 전화번호, 주소 같은 개인정보
- 비밀번호, API Key, 토큰

> 위 정보가 들어오면 봇이 처리를 멈추고 "지워 주세요"라고 안내합니다.

---

## 4. 무엇이 나오나요?

**결과물 1 — 요구사항 체크리스트**
꼭 해야 할 것 / 빠뜨리면 위험한 것 / 문서에 없어서 확인이 필요한 것을 한눈에 볼 수 있게 정리해 줍니다.

**결과물 2 — 제출문서 초안**
LLM 비교 보고서, 시스템 설계 문서, 실행 로그, 세 가지 문서의 틀을 잡아줍니다. 각 항목마다 "여기에 뭘 써야 하는지" 안내 메모가 달려 있습니다.

**결과물 3 — 확인 필요 목록**
미션 설명서에 나와 있지 않아서 봇이 답하기 어려운 항목들만 따로 모아줍니다. 강사나 운영자에게 직접 확인해야 할 내용입니다.

> 체크리스트 확인이 끝나야 초안을 생성합니다. 순서를 건너뛰지 않습니다.
```
