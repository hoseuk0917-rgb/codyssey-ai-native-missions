# 03. Few-shot 예시

## 예시 1. 공고문 요구사항 정리

### 입력

```text
아래 교육과정 공고문을 보고 지원 절차, 제출 준비물, 위험 요소를 정리해줘.
```

### 좋은 출력

```text
## 지원 절차
1. 회원가입
2. 과정 적합성 평가 응시
3. 선착순 신청
4. 현장 확인 등록
5. 최종 교육 참여

## 준비해야 할 것
- 상시 확인 가능한 이메일
- 현장 확인 등록 가능 일정
- 5개월 교육 참여 가능성

## 위험 요소
- 과정 적합성 평가는 1회만 가능
- 선착순 신청 기간을 놓치면 참여 어려움
- 4대보험 가입자는 장학금 대상에서 제외될 수 있음

## 확인 필요
- 현재 본인의 장학금 수혜 가능 여부
- 현장 등록일 참석 가능 여부
```

## 예시 2. 미션 설명서 제출물 정리

### 입력

```text
아래 미션 설명서를 보고 제출 산출물을 체크리스트로 만들어줘.
```

### 좋은 출력

```text
## 필수 제출물
- [ ] 모델 비교·선정 보고서
- [ ] 시스템 설계 문서
- [ ] 10턴 이상 실행 로그

## 문서에 반드시 들어갈 항목
- [ ] 3종 이상 LLM 비교
- [ ] 평가 축 최소 4개
- [ ] 페르소나 정의
- [ ] 시스템 프롬프트
- [ ] Few-shot 예시 3개 이상
- [ ] 환각 검증 질문 5개 이상
- [ ] 문맥 유지 검증

## 주의사항
- 개인정보를 로그에 직접 포함하지 않기
- 사실·수치·정책 답변은 근거 또는 확인 필요 표시
```

## 예시 3. 모호한 입력 처리

### 입력

```text
이거 제출용으로 정리해줘.
```

### 좋은 출력

```text
제출용으로 정리하려면 아래 정보가 필요합니다.

1. 어떤 과제 또는 공모전 제출물인가요?
2. 제출 형식은 README, PDF, 발표자료, 실행 로그 중 무엇인가요?
3. 반드시 포함해야 하는 요구사항 문서가 있나요?

자료가 없으면 먼저 임시 목차만 만들 수 있습니다.
```

## 예시 4. 조건 변경 반영

### 입력

```text
문체를 더 단호하게 바꾸되, 기존 체크리스트 구조는 유지해줘.
```

### 좋은 출력

```text
기존 체크리스트 구조는 유지하고 문체만 단호하게 수정합니다.

## 필수 제출물
- 반드시 모델 비교 보고서를 포함해야 한다.
- 반드시 시스템 프롬프트 전문을 포함해야 한다.
- 반드시 10턴 이상 실행 로그를 남겨야 한다.

## 확인 필요
- 실제 사용한 모델명과 사용일을 확정해야 한다.
- 무료/유료 요금제 여부를 명시해야 한다.
```
